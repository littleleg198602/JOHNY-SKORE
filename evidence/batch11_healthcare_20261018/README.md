# Dated applicant, roster and product observations

The new pure `FDA_APPLICANT_CHRONOLOGY` API compares up to four independently dated roster endpoints, four application snapshots and eight exact legal-name/jurisdiction pairs. Captures are explicit original-byte descriptors, bounded individually to 4 MB and collectively to 32 MB. It reuses the existing guarded roster/static FDA parsers; it does not collect data or adopt identities.

An exact listed row remains a literal dated source fact. Universe `PRESENT`/`ABSENT` states require an exact source-row declaration that all subsidiaries at that point are listed, with no conflicting omission/exclusion. The current adapter supports the explicit `SUBSIDIARIES OF THE COMPANY: This is a complete list of all subsidiaries of the Company as of [day].` declaration. No omitted-name negative is inferred from a normal roster or from the absence of an omission sentence. Jurisdiction mismatches, duplicate rows, same-day source conflicts and spellings remain separate. Identical versions are not independent endpoints. Neither matching endpoints nor differing rows proves an ownership interval or change.

Application comparisons group only the same source kind and role. They report literal rows appearing only in either capture; this is not a claim that a product was absent, withdrawn, assigned or owned. Product universes remain unproved. Company fields are not compared as applicant versions. Capture/knowledge clocks and roster point dates are separate, and approval is not ownership start. New outer knowledge is stamped on physical completion after supporting reviews.

`retained_review_plan.json` is the actual compatible dispatcher plan, and `source_review.json` is its current offline interpretation.
